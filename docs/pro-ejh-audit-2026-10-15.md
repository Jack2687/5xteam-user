# Pro 与 EJH 审计记录（2026-10-15）

范围：本地 chatgpt-space-merge 的 Pro 自动补货、Pro 管理及 EJH。未修改正式环境或另一个 Space 仓库。

## 本轮复现并修复

1. **手动停止后被自动恢复**：运行中的流程取消后原来记录为 interrupted，补货跟踪会重新启动已授权的后续流程。现在先持久化 stop_requested，再取消工作；迟到的状态写入、服务恢复和补货派发均保留停止意图。显式点击续跑才清除此标记。未提交且已停止的预留会撤销，候选选择不会再次自动领取该账号。
2. **删除账号遗留活动补货任务**：Pro 删除预检与邮箱通用删除原来未检查补货记录。现在按数据库中的活动任务拦截删除，覆盖 reserved、submitting、running、verifying、unknown、attention；终态任务允许删除账号并保留历史。
3. **过期额度影响当前与未来容量**：旧的 100% 额度会将可调度账号判为不可用，并扩大并发补货缺口。现在只有有效时间内且字段合法的额度样本参与容量扣减；过期或未来时间的样本不参与时间预测，可靠的并发规则仍可独立工作。保留原始窗口集合，避免丢弃某个窗口后误认为额度覆盖完整。
4. **采集及派发耗时绕过快照有效期**：原来部分时效判断使用采集开始时间，派发也未逐项复核时效。现在在采集完成及任务核对后更新时间，逐个派发前检查快照；过期时保留尚未提交的任务，等待新数据。

新增回归测试先在修复前复现以上问题，再验证修复、显式续跑、重启恢复、删除终态记录和并发缺口计算。

## 一并保留并检查的功能

- EJH 公共响应层兼容 data 为 JSON 对象或 JSON 字符串。认证及所有业务方法共用，保留 DES/ECB/PKCS5 协议和资金操作不自动重试的行为。
- 补货任务原子领取、预算占用、订单关联恢复、付款成功后的授权恢复、卡片占用、导入和迁移保护。
- 前端自动补货页面、菜单、构建产物及 Sub2 采集质量扩展说明。

## 验证边界

已通过 `go test ./... -count=1 -timeout 15m`、`go vet ./...`、服务器编译，以及前端类型检查、生产构建和 EJH、卡片分配、Pro VM、成本、迁移、推送分组、列表选择、质量分组等专项检查。采集完成时间的最后调整另行通过补货与停止流程专项测试。前端构建仍有现存的单个 JS 包超过 500 kB 的提示，不影响构建成功。

验证使用本地临时数据库和模拟接口，不产生真实订单。自动执行仍要求 Sub2 提供 strict=true、quality 与 load_known；缺少采集质量证明时拒绝自动执行。配套补丁只作为文档交付，未应用或部署到 Sub2。SQLite 调度仍按单实例设计；本次审计不构成对所有外部接口或生产运行情况的穷尽保证。
