# Pro 流程完成后的 Help 确认

空间合并、删除账户、API 商户、合并空间 2.0 各自保存确认记录，不随当前全局流程选项切换。Pro 列表显示等待、登录、Help 授权、提问、回答、确认六步；两个卡台的账号回款列表和弹窗显示简洁状态，悬停或点击可查看、复制完整回答。

Pro 列表的 OAI 确认流程最下方另有“结果情况”入口，点击查看当前完整回答、询问时间及历史回答，并可复制。尚未收到回答时明确显示“暂无回答”；查看结果只读取已有记录，不重新发起询问。

## 自动与手动

- Pro 全自动配置中每种流程单独开启，默认等待 300 秒、重试间隔 300 秒、总尝试 3 次。新完成时记录计划；启用开关不自动补问历史账号。
- 已完成的历史账号可以点“开始确认”，等待中可以“立即确认”，失败、未确认、待核实或停止后可以“重试确认”。手动任务可以独立于自动开关执行；账号整体已停止时先恢复账号流程。
- “停止确认”只停止 Help 确认；停止账号全自动也停止确认任务。已发送的提问无法撤回，停止后不接受旧任务回写。
- “OAI 已确认”后终止自动询问。明确“已失败”或网络失败按次数和间隔重试；内容不明确显示“待核实”，不自动重复提问。

## 会话与结果

沿用原有账号密码、2FA 登录引擎及代理选择，在同一个 curl 会话和出口上完成 Help OAuth 账号选择、回调、身份校验及询问。Help 使用其自己的 OAuth 授权地址，不使用 SIWC 凭据。先核对 Help 身份与目标邮箱，才发送只查询退款状态的问题。

Help 的页面访问、OAuth 跳转、身份读取及对话共用原 OAuth 的浏览器请求封装，统一 Chrome 指纹、默认请求头、Cookie 同步和本轮固定代理。先打开 Help 页面建立站点会话，再选择当前账号并经过 callback、login-success 返回页面。登录页面的 root loader 提供 Help 专用 accessToken、签名 sessionIdToken 和 helpCenterSessionId；只解析 JSON，不执行网页脚本。支持接口使用这份 Bearer Token，并再次校验邮箱，不能以 ChatGPT 的 AT 或 Cookie 代替。

Help Token、签名会话、Cookie 与固定代理使用应用主密钥单独加密存储，不放入公开账号资料。身份读取暂时断线时保留加密候选会话，恢复时仍须校验身份才允许提问。只读请求可在同一会话重试网络错误；OAuth 回调和发送问题不自动重发。删除账户前的登录阶段尝试预备 Help 会话，授权失败不会伪造确认或阻止原删除登录。删除后会话若已失效且账号无法登录，会展示真实失败原因。

发送前持久化意图，保存对话和消息编号；断线或服务重启后优先读取原对话，不盲目重发。仅接收匹配账号、对话、用户提问的完整助手回答；用户问题、思考过程、增量片段不作为成功依据。末行“已成功”还需正文明确退款已发起/处理且没有冲突；回答按纯文本展示。

“OAI 已确认”表示 Help 的回答确认已发起/处理退款，不等于银行已到账。不会修改卡台回款金额、成本、利润或销卡条件。

## 验证

离线协议测试覆盖原会话及代理、Help 授权回调和邮箱校验、完整回复流、用户提示误判防护、发送前停止、中断续读与删除前预备。Go 测试覆盖四模式配置、完成触发、历史记录投影、加密会话、任务去重、重试、停止、服务恢复及手动补问。真实上游验收须使用用户明确指定的测试账号，不重放合并或删除。
