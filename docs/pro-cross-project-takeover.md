# 跨项目接管

入口：**Pro 自动补货 → 补货配置 → 跨项目接管**。升级后默认关闭。

## 配置

1. 环球项目选择“提供接管”，EJH 项目选择“接受接管”。两边先关闭该功能，分别保存对方 Space 地址、后台登录账号和密码。
2. 两边 Pro 推送必须连接相同的 Sub2 地址和管理员账号。接受方勾选要支援的分组，必须包含本项目监控组，且属于本项目推送组；不能与提供方的常驻推送组重叠。
3. 两边测试连接后启用。双方自动补货也需启用并处于自动执行模式。接管设置不会修改既有预算、熔断、卡台或每日 EJH 合并设置。
4. 接受方设置提前准备分钟、恢复至少就绪账号数、连续确认次数。提供方设置接管至少就绪账号数、检查周期。默认提前 10 分钟、至少 1 个、连续 3 次、每 10 秒连接。

对方地址应为当前容器能够访问的地址。两个独立容器的 `127.0.0.1` 指向各自容器，不能直接用它访问另一个容器。可使用可达的服务器地址及对应端口，或同一 Docker 网络中的服务地址。公网连接建议使用 HTTPS。

## 自动交接

- 时段来源只有接受方的“完全禁补”时段，支持多段、重叠和跨午夜。允许某一卡台补货的例外时段不触发跨项目接管。
- 提前准备开始，接受方暂停新的自动补货，原在途继续。等原批次结束后，提供方给自己已推送、可服务的环球账号添加临时组，再统一评估常驻组和支援组。
- 同一 Sub2 账号的并发、等待、费用和容量只算一次。接管供给只计提供方的环球账号；接受方即将退出的 EJH 账号只贡献实际需求，不虚增可承接容量。补货仍遵守原批次、预算、冷却、失败熔断和卡台开关。
- 时段结束后，接受方等对方在途完成，再按自己的 EJH 容量恢复补货。环球支援暂时保留。只有新一轮监控证实自有账号数、容量和已启用的时间供给条件满足要求，连续确认后才交还。
- 同时属于多个组的账号返回的是账号总负载；恢复容量据此保守核验，不猜测每组流量比例。
- 交还只删除本功能实际添加的分组，不删除原分组、不切换全局调度、不改账号归属，不触发新的开通或合并动作。

## 异常与关闭

连接/授权失败时保留现有支援，授权到期暂停新的接管补货。后台会继续尝试连接，监控大屏显示交接状态和错误。不会因为断线直接撤掉账号。

关闭开关是“安全交还”请求，已有支援仍等接受方恢复后撤回。正在交接时不能改角色、对方地址或接管组，以免丢失原临时分组记录。手动任务、额度巡检、退款以及每日 EJH 定点合并独立运行。

密码加密保存，不在接口返回。对方通过独立的账密认证接口通信，只交换接管状态，不传递银行卡、Sub2 密码或账号令牌。状态、权限期限及临时分组记录持久化，进程重启后继续核验。
