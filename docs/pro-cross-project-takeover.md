# 跨项目接管

入口：**Pro 自动补货 → 补货配置**。跨项目连接默认关闭，需要自行填写、测试并启用。

## 配置

1. 环球项目选择“提供接管”，EJH 项目选择“接受接管”。两边先保存对方 Space 地址、后台登录账号和密码，保存不依赖对方配置或在线状态；两边保存后再分别点击“启用接管”，启用时校验角色、账密和分组。测试连接不改变启用状态。
2. 两边 Pro 推送连接相同的 Sub2 地址和管理员账号。EJH 项目在 **跨项目接管 → 接管分组** 中自行多选，首次默认带入 Pro 推送分组，之后独立保存。点击“刷新分组”读取 Sub2 当前名称，保留现有勾选；已失效分组会提示。须包含 EJH 的监控组，不能与环球的常驻推送组重叠。
3. 在 EJH 的 **每日禁补时段** 中，只给需要支援的时段勾选 **环球接管**。未勾选的时段照常禁补。已有时段、新增时段默认均不勾选。选择“允许卡台”的本项目例外时段不能再勾选跨项目接管。
4. 提前准备默认 **0 分钟**，即到点接管；可自行设置提前量。提供方默认每 **10 秒**检查连接。两边自动补货都需启用并处于自动执行模式。

例：02:00～08:00 不勾选，17:00～20:00 勾选。只有 17:00～20:00 由环球支援；20:00 开始撤回临时分组，两边各自运行。

对方地址使用可达的服务器地址及对应端口，或同一 Docker 网络中的服务地址。容器内的 `127.0.0.1` 指向自身，不能用于连接另一个容器。

## 分组与补货

- 已有且仍可服务的环球账号保留原分组，追加 EJH 勾选的接管分组。新号完成推送时也追加相同分组。结果等于“环球原推送设置中的全部分组 + 本次接管分组”，自动去重。
- 推送已成功但临时挂组失败时，保留账号与挂组记录，后台继续补挂，不重复创建下游账号。监控确认挂组就绪后才计入接替完成。
- 接管期间统一监控环球监控组和 EJH 全部接管分组，同一账号的并发、等待、费用与容量只算一次。接管供给只计环球自身账号，EJH 账号保留实际需求但不虚增供给。
- 每次接管开始记录当时勾选的接管分组；接管期间修改选择，下次接管生效。普通推送设置不覆盖该选择。
- 补货沿用原批次、预算、冷却、失败熔断和卡台开关。接管准备时 EJH 暂停新自动任务，已启动流程继续。

## 时段结束

到结束时间就开始撤回 **本功能实际追加的分组**，不等待 EJH 容量恢复，不等待其他账号开通批次结束。环球恢复自己的监控与补货，EJH 也恢复自己的规则；尚在开通、结束后才推送的新号只用环球原推送分组。

两边每秒检查已记录的结束时间；具体撤组完成时间取决于 Sub2 响应和账号操作锁。撤组失败保留记录继续重试。即使两项目之间断线，环球仍按已记录的结束时间撤组。

支持多段和跨午夜。重叠时，未勾选接管的完全禁补时段优先；提前准备不会侵入这些时段或本项目允许卡台的例外时段。

## 关闭与保护

时段内网络中断保留已有分组，短期购买授权到期暂停新增。手动提前关闭接管开关仍按 EJH 恢复就绪条件安全交还，最迟到本次时段结束按时间撤回。

只删除记录为临时追加的分组，保留原分组及人工添加的其他分组。不改账号归属，不自动触发合并。每日 EJH 定点合并、手动任务、额度巡检和退款独立运行。

密码加密保存且不由接口返回。临时分组、状态、结束时间持久化，重启后继续处理。业务数据、财务数据、银行卡配置不通过项目间接口复制。
