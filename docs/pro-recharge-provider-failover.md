# Pro 全自动第二步失败后的主备切换

在「Pro 全自动配置 → 高级设置」配置：

- **第二步失败换号次数**：首次账号之外，当前主供应商最多再领取几个账号，范围 0～10。
- **切换供应商后账号尝试次数**：主供应商本轮次数用尽且第二步仍失败时，交换主启用与备启用；切换后总共领取几个账号，范围 0～10。默认 0，关闭自动切换。

例如前者为 2、后者为 3：主供应商最多 3 个账号，切换后最多 3 个账号，整条任务最多 6 个账号。手动全自动、定时全自动、自动补货使用相同规则。只有第二步失败触发换号；每个新账号从第一步登录开始。

主备交换保存到全局配置，任务结束不会切回。后续新任务使用新的主供应商；它们再次耗尽自己的主供应商尝试次数时，才可能再次交换主备。每条任务最多切换一次。已经在执行的其他任务继续使用启动时固定的供应商；同时触发相同交换的任务不会互相切回。

每条任务启动时固定次数、主备供应商和购买意图。切换后保持原套餐、卡台、模板及推送目标，付款使用备用供应商自己的地区、接口和密钥；不把备用供应商默认套餐覆盖到本任务。供应商保存的默认套餐仍供后续新任务使用。原账号、原订单和未决付款占用保留。整个过程通过根账号和后继账号衔接为一个任务，定时进度会跟随最后一个账号；补货每次实际尝试仍单独计入次数和费用预算，沿用原批次。

没有新账号、备用密钥不可用或主备配置被人工改为其它组合时，任务显示等待原因，不会部分交换或创建重复后继。补货仍受预算、并发、禁补时段、版本、模板与停止检查约束。停止任一成员会停止整条任务。没有保存切换预算的历史任务不会因升级自动恢复。

验证使用临时 SQLite 数据库和本地模拟供应商，覆盖三个入口、成功及耗尽、重启、并发、主备持久交换、后续任务再次切换、备用配置缺失、模板变化与补货预算；不执行真实开通付款。
