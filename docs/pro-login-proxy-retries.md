# Pro 登录代理故障与重试

配置入口：Pro 管理 → 全自动配置 → 高级设置 → 重试间隔（秒）。

- 尚未付款的登录阶段，代理隧道建立失败会终止本轮客户端；等待配置的完整间隔后，保留原账号、原卡和付款身份，重新建立代理会话。
- 代理连接恢复最多额外重试 3 次，独立于账号业务失败重试次数。停止全自动会取消等待，不发起下一轮。
- 每次失败后安排重试时读取最新配置。已经公布的下一次执行时间保持不变，修改配置在下一次安排时生效。
- Pro 连续会话内部不再进行 0.6/1.3 秒的隐式 HTTP 重试。可选页面预热即使忽略了代理异常，也不能继续通过同一失败隧道发送登录请求。
- 成功登录、开通、获取凭证仍沿用同一客户端、代理、Cookie 和指纹。已有付款成功或付款待确认时，不通过本策略重新登录付款；保留原有后续恢复路径。
- 出口 IP 观测仍是诊断，不因为 Cloudflare trace 不可用或 IP 变化单独阻断流程。代理故障判定来自实际登录请求。
- 全自动弹窗分别显示账号重试、代理连接重试及下一次执行时间。全局网络重试和补货监控周期不是这里的重试间隔。

`CONNECT tunnel failed, response 504` 表示代理未能建立目标连接，不能据此判断账号失效。每轮会更新支持会话轮换的代理会话标识；固定代理地址无法由应用凭空更换出口，代理服务持续不可用时会在有限重试后明确报错。

验证覆盖：真实协议的离线 HTTP 仿真、代理预热失败中断、POST 不隐式重放、同账号重试成功及耗尽、配置变更、等待期间停止、付款结果未知/成功防重，以及原有独立 OAuth 流程。

## 已开通后的授权恢复

已有成功订单时，手动“重试并继续”和补货任务的自动恢复只重新登录原账号，核对账号和空间与原付款订单一致，再获取 RT/AT。恢复从排队、登录到授权全部显示在第三步，前两步保持完成；恢复登录失败也只将第三步标为失败，不重新开卡、换号或付款。

补货已付款恢复沿用原有调度：最多 `失败重试次数 + 1` 次恢复，两次恢复开始至少相隔 `max(30, 重试间隔)` 秒，并由补货监控周期触发。普通手动开通发生授权失败后，可点“重试并继续”恢复；本次没有新增无限自动恢复。出口 IP 诊断不一致本身不触发重新登录。
