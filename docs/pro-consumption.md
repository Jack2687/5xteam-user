# Pro 消耗额度

Pro 管理账号列表在“推送”和“5小时”之间显示“消耗额度”，与 Team 轮转的账号流程列表使用相同口径：Sub2 最近 90 天统计的标准消耗，第二行显示用户消耗，均保留四位小数，并显示最后成功查询时间。不是 5 小时／7 天的额度使用百分比，也不是本地历史累计总额。

- 单个“查询额度”、勾选后的“批量查额度”、现有自动额度检测，共用查询入口。打开或刷新列表只读取本地快照，不额外请求下游。
- 复用 Sub2 的 `QueryTotalCosts`；优先 `total_standard_cost`，兼容 `total_cost`，用户消耗读取可选 `total_user_cost`。
- 未查询显示“未查询”，用户金额缺失显示“用户 --”，真实零金额显示 `$0.0000`。CPA 和 vm2api 与 Team 一样显示“不支持／不统计”。
- 消耗查询与额度查询并行、独立保存。消耗失败不影响额度判断，保留上次成功值和时间并记录日志；额度失败仍可保存成功取得的消耗。
- 同一下游绑定沿用 Team 的非递减快照规则；更换下游账号或供应商清空旧快照；连接地址／管理员变化时不展示其他连接的数据。重新导入邮箱凭证、移回邮件管理、服务重启不会丢失当前快照。
- 不增加合并触发条件，不改付款、开卡、合并、移出流程。
