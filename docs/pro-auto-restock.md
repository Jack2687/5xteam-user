# Pro 自动补货

与 Pro 管理同级的独立菜单，包含监控大屏、补货配置、决策与记录。“查看”打开详情弹窗，支持 Esc 关闭和焦点返回。原数量型定时任务的配置与计算公式保持原状，共享账号领取与卡片占用保护。

## 启用

1. 更新并部署 Space；数据库自动添加补货表，默认关闭、观察模式。
2. 在 Pro 管理配置 Sub2 推送、请求并发、开通工作并发、目标母号、供应商和卡片。
3. Sub2 需支持下述采集质量扩展，并开启实时监控。
4. 读取分组，单选推送目标中包含的监控组，使用不共享账号的专用组。
5. 先观察容量、消耗和实际就绪耗时，设置水位、批量、在途、预算、冷却，再切换自动执行。

后台达标后调用现有全自动 Pro：登录、付款、新授权、推送、额度巡检、合并及移出。浏览器关闭不影响运行。“立即评估”在自动模式下会执行符合规则的任务。同池旧定时任务仍会按原策略补货，页面提醒但不擅自关闭。

## 决策和到货延迟

时间不足与持续并发独立判断，净缺口取最大值，再应用批量、在途、数量、预算、池上限与熔断。最低备用默认 0；空池无账号侧需求时不自行开通，需要冷启动保障时配置备用。

状态为预留、启动确认、全自动执行、已推送待核验、就绪。逐号核验 Sub2 真实 ID、原分组、模型和可调度状态；无需等待整批或额度接口。已启动不等于当前容量，仅可信 ETA 的在途进入未来供给。

预计就绪覆盖工作排队、登录、开通、授权、推送和监控核验。历史足够时采用 P90，并按最新阶段的历史剩余耗时更新；不足时使用回退值。ETA 锚定原阶段时间，不随每轮检查向后漂移。超时任务保留在途但不承诺未来容量。提前补货取配置水位与保守到货时间加余量中的较大值。

新快照仍有缺口且冷却结束就继续补，不要求先恢复正常。紧急账号排队可缩短冷却，但不能绕过硬上限。流量下降只撤销尚未提交的多余预留；已付款继续核验原订单。付款成功但授权中断时按原重试限制恢复登录和授权，不重复购买。结果未知保留订单、预算及在途，在 Pro 管理核验原订单。

## 额度与使用时限

时间预测只采用同一可信供应商、套餐、国家、点数配置及相同额度窗口的百分比消耗样本，以 15 秒步长模拟在途、重置和期限。金额与 Token 不换算成额度。套餐混用、窗口不同或样本不足时暂不可估，可靠并发规则仍独立生效。

延续原 ProPushStartedAt 起算的等待时限，重推不重置。展示到期预计闲置的等效额度，可配置新号最低预计使用比例限制普通时间补货；0 关闭保护，持续并发和显式备用仍独立生效。时间目标因期限或在途上限不可达时暂停时间侧新增并提示。合并或移出后是否仍提供容量按 Sub2 实际状态计算。近期需求外推不能保证每号在期限内恰好耗完。

## Sub2 采集质量扩展

Space 校验快照时效、分页完整性、组成员、容量、每号 load_known 和 quality。故障时保留最近有效数据和时间戳，但不以旧数据开通。共享组账号暂停新增；大面积错误或过载按可配置比例暂停。

当前 Qerkai-sub2api 缺少 quality 时，Space 拒绝启用自动执行。配套补丁位于 `docs/integrations/qerkai-sub2api-monitor-quality.patch`，基于提交 `5dcb39c68db1f6784e77de3b62d41900da01af10`。本次未修改或部署另一个仓库。补丁绕过负载短缓存，返回完整性和 load_known；strict=true 且部分失败时返回 503，同时修复 Redis pipeline 缺失值掩盖后续错误。

在 Qerkai 仓库根目录执行，按实际位置调整补丁路径：

```powershell
git apply --check --ignore-space-change ../chapt-space-user/docs/integrations/qerkai-sub2api-monitor-quality.patch
git apply --ignore-space-change ../chapt-space-user/docs/integrations/qerkai-sub2api-monitor-quality.patch
cd backend
go test ./internal/service ./internal/repository ./internal/handler/admin -run TestProRestockQuality
```

然后按该项目现有方式构建部署 Sub2。补丁已通过隔离 overlay 编译和行为测试，应用检查通过，不代表已部署。

## 持久化及预算口径

SQLite 原子预留账号、预算与决策，派发前 CAS 领取；付款走原幂等机制。重启恢复跟踪。已提交任务保存加密原推送目标，配置变化仍核验原连接及组。重新导入凭据保留本机归属，跨服务器迁移不携带外部补货锁，仍检查原下游身份。适用于现有单进程部署，不支持多实例共享同一 SQLite 同时调度。

金额按配置的每号保守成本预留记账，不是供应商实付账单，也不包括手动和旧策略支出。结果未知跨日仍占用预算；已提交失败成本保守保留，未提交撤销释放。卡片单号占用、累计开通上限及付款防重仍走原机制。

额度由独立 4-worker 队列采集，不阻塞并发采样；大池整轮刷新可能超过配置周期，过期样本不参与时间决策。决策按变化或每 30 秒存档，配置保存及熔断重置也留记录。保留天数仅清理决策快照；任务和订单保留用于防重。

## 验证

覆盖双规则取最大值、批量硬上限、在途冷却、提前到货缺口、额度重置和套餐变化、合法零负载与缺失过期数据、上游异常、逐号就绪、付款后恢复、未知结果找回原订单、原子领取预算、重启和迁移。浏览器验收使用本地假数据，不产生真实订单。
