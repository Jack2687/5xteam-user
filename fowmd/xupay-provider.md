# 序付开通供应商

在 Pro 管理 → Pro 全自动配置 → 开通设置，选择 **序付 · XUPAY**。

- 地址填写序付站点根地址或 `/api/v1` 地址。当前部署为 `http://104.160.172.162:5496/api/v1`，也支持自己的 HTTPS 域名。
- API Key 使用序付开发者中心生成的密钥，不是登录密码。保存后点击「刷新国家与套餐」，供应商账户页可以查询余额、等级和服务费。
- 供应商独立保存地址、密钥及套餐；切换不会把另一家密钥带过来。未填密钥不能开通。新增选项不会自动切换原来的供应商。
- 当前支持 Pro 5x、Pro 20x。序付产品 ID 分别是 `pro5x`、`pro`；不将 50x、Team、升级或 Codex 点数误映射成其他套餐。
- 地区支持 PH、US、JP、SG、GB、EG、TR，真实目录及启用情况以序付返回为准。首次配置可先保存；报价缺失时不显示虚构价格。
- 确认并保存使用条款后才能创建订单。Space 的选卡、模板、分时开通、登录、开通后 RT/AT 与推送流程继续使用原逻辑。

## 后台调用

Space 后台使用 `Authorization: Bearer <序付 API Key>` 提交 `POST /api/v1/orders`，发送本次完整 Session、所选卡片、套餐、地区、`workflow=subscription`、`seats=1`、`accepted=true`、`keep_renewal=false`。账单资料由序付后台从已启用正式池抽取，Space 不生成或覆盖。

`Idempotency-Key` 固定使用 Space 原订单 ID，完整请求与供应商地址、密钥以现有加密快照保存。请求超时只能重放原订单、原参数及原幂等键；拿到序付订单 ID 后只调用 `GET /api/v1/orders/{id}` 查询。首次提交前持久记录提交标记，避免重启或超时后遇到限流、过期 Session 等拒绝时把已受理的订单误记失败。

序付自行处理提链、付款、订阅生效核实和关闭续费，其代理与账单设置在序付管理。Space 浏览器只访问 Space 的后台接口，不直接提交序付付款或调用上游付款接口。

## 状态与金额

| 序付结果 | Space 处理 |
| --- | --- |
| 已受理、排队、付款中 | 开通中，按现有 5 秒/15 秒节奏查询 |
| 已付款，订阅生效仍在核实 | 保留订单并继续查询，禁止新付款 |
| 已付款，订阅生效待核实 | 待人工核查，保留原账号和占位，在序付支付全监控核实后查询原订单 |
| 已付款且订阅生效 | 开通成功，可继续 Space RT/AT 和推送步骤 |
| 已生效但关闭续费失败 | 保持开通成功，单独提示关闭续费失败，在序付续费管理接续 |
| 付款未知或需要额外验证 | 待人工核查，不重发付款 |
| 明确失败或取消 | 失败，按原失败处理；未知、冲突及无效响应不视为失败 |

已确认付款的状态不能被后续异常覆盖成未付款。新建付款的保护不会阻止已付款账号继续 RT/AT、推送等后续流程。

序付余额、冻结及服务费以整数分返回，界面除以 100 显示为 R；银行卡实际扣款按返回币种和最小单位单独显示，不能把服务费当作卡片支出。

查询和错误投影只保留需要的订单字段、固定错误分类及状态；不返回完整 Session、银行卡号、CVV、API Key 或原始上游响应。生产配置和真实密钥不放入源码。

本次验证采用本地模拟序付 HTTP 接口与隔离浏览器，覆盖幂等回放、超时后限流、配置切换、已付款保护、订阅确认/续费状态、金额单位与密钥隔离；不进行真实银行卡扣款。
